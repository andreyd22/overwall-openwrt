# 0.1.0 open beta acceptance — 13 November 2026

- OpenWrt 25.12.6 x86-64 QEMU: native APK signed package installation;
  17 parser/security checks, real LuCI RPC ACL/async-job checks and DOM behavior.
- Two DHCP LAN clients: TCP and UDP forwarded through isolated VLESS/WireGuard;
  stopping either tunnel blocks direct fallback; explicit disconnect restores it.
- Isolated real backend + Valkey over verified lab TLS: device pairing, pending
  approval, one-time exchange, quota portal for both clients and automatic
  recovery after API-confirmed access restoration. No production users involved.
- OpenWrt 24.10.8 x86-64, 256 MB QEMU: signed opkg feed, automatic installation
  of runtime dependencies, remove/reinstall, native RPC registration, VLESS
  configuration and real HTTP forwarding through Xray 25.1.30.
- Memory workload: two LAN clients, 8 concurrent TCP streams each, 60 seconds
  per protocol. First 768 MB run: system peak about 110 MiB by
  MemTotal-MemAvailable; Xray RSS up to 35 MiB, zero transfer errors.
  Repeat with 256 MB guest: VLESS peak 99.1 MiB system / 34.6 MiB Xray RSS;
  WireGuard 93.8 MiB system; zero transfer errors on both clients. Isolated VLESS has no TLS;
  periodic connectivity checks are paused in the repeat because the fixture
  intentionally lacks unrestricted public egress. Router-specific services,
  TLS/Reality and connection counts can increase memory use.
- Minimum 256 MB RAM, recommended 512 MB; 50 MB free persistent storage.
  These are beta admission requirements, not certification of every router.

Pending: physical ARM/MIPS router acceptance, throughput guarantees, OS captive
window behavior and full provider/bank payment return from a captive network.
The portal exposes the Overwall site; for beta payments use a phone's cellular
connection. Official OpenWrt catalog publication is pending.

Backend release: ordinary suite passed 1152 tests; focused client/security
suite passed. Managed suite passed 1360 tests but has one pre-existing failure
in accountDeletion.test.js: expected empty device index after a durable deletion
fence is lost, observed one entry. Reproduced using unmodified origin/main
clientApi.js; durable access denial itself passes. This release does not change
that deletion path. The initial managed run also exposed a missing disposable
Valkey on port 16579; rerun after provisioning that test fixture produced the
single baseline failure above. No production database was used in tests.
